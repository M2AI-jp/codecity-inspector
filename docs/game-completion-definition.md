# ゲーム完成条件

CodeCity Inspector を「完成」と呼ぶのは、以下を**同じrevision・同じURL・同じ実ブラウザ**
で全件確認し、最後にプロダクト所有者がプレイ承認した場合だけです。

## 1. 入力が街へ反映される

- `/api/town` の同一 WorldPlan から地区、地表、道路、建物、NPC、fact、nav を描く。
- ファイルと建物、静的参照と道路、factと会話を相互に追跡できる。
- 異なる3リポジトリで、入力差が建物数、地区、道路、表示factの差になる。
- 観測、推定、不明を混同せず、人が意味分類を確認・修正できる。

## 2. 画面が製品品質である

- 旧素材、固定背景、互換alias、CSS図形、未承認画像へのfallbackがruntimeに存在しない。
- 登録素材は Art Contract N1–N9 を全通過する。
- prefab再組み立てはマスターボードと建物座標100%一致、SSIM 0.85以上。
- 1280×720と1920×1080を整数zoomで表示し、画素密度、相対寸法、UI可読性が一致する。
- 品質基準画像と横並びでLeadが確認し、所有者が視覚品質を承認する。

## 3. 移動と衝突がゲームになる

- north / east / south / west に専用idle 2f、walk 6f、interact 2fがある。
- 入力方向と向きが一致し、移動中は10fpsで歩行し、停止時はidleへ戻る。
- 全frameの足元pivotは (32,120) でnav nodeからずれない。
- 建物、家具、水、崖を横断できず、door、bridge、stairsだけを規則どおり通れる。
- キーボード、クリック、タッチで同じ到達可能性になる。

## 4. 建物と室内が成立する

- 市庁舎、宿屋、一般M住宅の3種でdoor tileを経由して進入・退出できる。
- 入室時はその建物のroofだけが非表示になり、外の街と室内が同一画面に共存する。
- interior矩形は外観footprintと一致し、床、壁、家具、NPCが実素材で描かれる。
- playerはcutaway中も前景に見え、隣接建物は透過しない。

## 5. 会話・調査・UIが成立する

- ユーザー提供の `ui-dialogue-frames.png` を正規化して切り出した会話枠を実際に使う。
- 話者、本文、選択肢、根拠区分を読め、会話中の対象NPCが視覚的に分かる。
- 手帳取得 → 問い選択 → 異なる3方式の調査 → 市庁舎へ帰還 → 回答 → 結果説明を完走できる。
- 目的、現在の操作、閉鎖理由、未確認理由を画面内で理解できる。

## 6. 保存・復元・品質保証

- repository identityとinspection digestごとに調査状態、player位置、設定を保存する。
- reload後に同じ状態へ復元し、「最初から」で当該保存だけを確認付きで消せる。
- 新規開始と復元開始の両方で完走する。
- console error 0、unhandled rejection 0、network failure 0。
- 同一WorldPlanの2回描画はPNG hashが一致する。
- Leadが実ブラウザで全項目を再確認し、証拠画像と判定表を残す。

## 完成ではない状態

- WorldPlanだけ生成できる。
- 固定デモだけ美しい。
- 1枚絵の上をキャラクターが滑る。
- 方向だけ切り替わり歩行frameがない。
- 建物が茶色い矩形になり、建物全体を半透明にする。
- 素材数、テスト数、console error 0だけを完成根拠にする。
