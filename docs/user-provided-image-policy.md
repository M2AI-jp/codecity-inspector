# ユーザー提供画像の扱い

更新日: 2026-07-22

この文書は、CodeCity Inspectorで画像を受け取り、保存し、加工し、ゲームへ組み込むときの最上位規則です。目的は、ユーザーが直接渡した画像を失わず、Codex生成物と取り違えず、承認されていない用途へ横流ししないことです。

## 1. 画像ごとに四つを別々に記録する

一つの分類名ですべてを表しません。必ず次の四項目を独立して記録します。

1. `origin` — そのバイト列を誰または何が作ったか。分からなければ `unknown` のままにする。
2. `custody` — 誰がこのプロジェクトへ渡したか。ユーザーが添付または提供した同一バイト列だけを `user-direct` とする。
3. `approval` — どの用途に使ってよいか。背景、人物の同一性、参考、切り出しなど、用途ごとに承認・拒否・未確認を分ける。
4. `protection` — どこまで失われにくく保存できているか。作業ツリーだけ、Git履歴あり、版管理済み、外部保管済みを区別する。

したがって、AIが作った画像でもユーザーが直接添付した同一バイト列なら、`origin` は外部AIまたは不明、`custody` は `user-direct` です。Codexが生成した画像は、ユーザーが後から限定用途で採用しても、`custody` を `user-direct` へ変えません。承認は出自を書き換えません。

## 2. 「ユーザーが直接提供した」と認める証拠

次のいずれかを、SHA-256と構造化した証拠で確認します。

- 現在または過去の会話へユーザーが直接添付した画像
- 受付台帳に `providedBy: human` と記録された画像
- ユーザーが直接提供したと明言し、既存バイト列と添付のSHA-256が一致した画像

自由文だけでは足りません。可能な範囲で、受付manifest ID、元パス、受付commit、Git blob、添付ファイル名、観測SHA-256、日時を台帳に残します。不明な値は推測せず `unknown` とします。

## 3. 使用の優先順位

同じ対象に複数画像がある場合は、次の順です。

1. ユーザーが最新の指示で、その用途の正規画像として指定したもの
2. 同じ対象についてユーザーが直接提供したもの
3. ユーザーがその用途に明示採用したCodex生成物
4. ユーザー提供画像から作り、原画比較に合格した派生物
5. 未承認候補

新しい画像が存在するだけでは、旧画像を置き換えません。用途ごとの明示指示が必要です。古い承認を別用途へ広げません。

## 4. 原本の保存

- ユーザーが直接提供した原本は `art/references/user-provided/` に受領時のバイト列のまま置きます。
- 原本を上書き、削除、再圧縮、色変換、リサイズしません。
- 新版は別recordとして追加し、旧版を別ファイルで保持します。見つからない旧版もloss/tombstone recordを残します。
- ファイル名を変えても、元名、元パス、SHA-256、受付証拠を残します。
- 原本の欠落またはハッシュ不一致はhard failureです。
- 作業ツリーにあるだけの状態を「完全保護済み」と表現しません。現在の22枚は `worktree-protected-pending-versioning` です。
- commit、stage、push、配布物への追加はLeadだけが判断し、ユーザーの許可または依頼なしに実行しません。

## 5. 派生画像

- 派生物は原本と別パスに置き、`sourceId`、`sourceSha256`、加工または生成方法、crop/mask、出力SHA-256、比較証拠を記録します。
- きれいに切り出せる画像は、まず原本からの切り出しを使います。
- 生成AIは、足りない向き、歩行中間、開いた扉、遮蔽解除後の背景、必要な前景など、原本だけでは足りない部分に限定します。
- 人物、建物、UI、色、形、密度を実装都合で別デザインへ変えません。
- 「似た雰囲気」は同一人物・同一建物・同一UIの合格条件ではありません。
- 派生物を `user source`、`user original`、`user-provided` と表示しません。
- 不合格の派生物も、削除せず `quarantine` として失敗証拠と比較に残します。runtimeからは参照しません。

## 6. ゲームでの使用方法

使用可否は一つのbooleanで表さず、少なくとも次を分けます。

- `directWholeImageRender` — 完全画像をそのまま全面描画してよいか
- `fixedCropInput` — 指定cropの素材としてよいか
- `nineSliceInput` — 9-sliceの入力としてよいか
- `generationReference` — 不足画像を作る参照としてよいか
- `fullSheetRender` — シート全体をUIやゲーム画面へ直接表示してよいか

現在の町全体画像は、ユーザーの明示指示により原寸の完全画像をruntime背景へ直接使用できます。この許可は、SHA-256 `39102cbaed6745d658b8449cc7197f8454fb8492b4679f288de16c204e82d607`、1586×992の `target-town.png` だけに適用します。別の生成背景へ移し替えません。crop、stretch、1536×1024への変形もしません。

背景を使っても、当たり判定、入口、扉、前景、室内、NPC、会話は省略しません。背景の見た目とゲームオブジェクトの位置が一致しなければ不合格です。

UIシートは、承認済みのcropまたは9-sliceの入力として使えますが、シート全面の直接表示や全面stretchを許可した意味ではありません。

## 7. キャラクター固有の規則

プレイヤーの唯一の現行原画およびキャラクター視覚スタイルのauthorityは、ユーザーが直接提供した `character_style_authority_20260722_v1.png`、SHA-256 `446080b87192f13acd67f7410cfbfeb152830d93571edd5a9198406cef0b6932`（1402×1122）です。現行の人物同一性、フレーム切り出し、欠落フレーム補完は、このシートだけをauthorityとして扱います。

- 灰色から薄紫の髪、髭、深緑の胴着、黄土色の縁取り、生成り色の袖、白から薄灰色の下衣、暗色の靴を保ちます。
- 顔、年齢感、頭身、髪、髭、服、配色、輪郭を別人へ変更しません。
- 原画にない向きと歩行中間だけを、同一人物として補います。シートにある正面、側面、背面、歩行、ジェスチャーはすべて現行authorityです。
- NPCは別人にできますが、原画のpixel density、頭身、輪郭、陰影の言語を共有します。
- 旧ユーザー提供 `character_style_reference_sheet.png` は原本として不変のまま残しますが、現行プレイヤー同一性・現行キャラクター視覚スタイル・現行フレーム生成へのpromotionだけは新しいauthorityによりsupersededです。旧原本を削除、上書き、別バイト列への置換はしません。
- 青い帽子、長い青いコート、鞄の `character_visual_master.png` はCodex生成物です。過去の限定的な参考承認は記録として残しますが、現在のプレイヤー同一性、現行キャラクター視覚スタイル、runtime用途ではrejectedです。
- 青い既存player atlasは削除せず隔離し、runtime参照を外します。

## 8. 評価で毎回確認すること

各evalは、明示要件だけでなく、ゲームとして当然必要なのに言語化から漏れやすい項目も毎回確認します。

- 原本が存在し、SHA-256と寸法が一致するか
- origin、custody、approval、protectionが混ざっていないか
- runtime画像から原本と変換工程まで追跡できるか
- 原画と派生物を横並びにし、別人、別建物、別UIになっていないか
- 原寸とゲーム表示寸法の両方で、色、輪郭、足元、pixel densityが合うか
- ユーザー提供画像があるのに、生成物や仮画像を優先していないか
- 背景許可が別の画像へ横流しされていないか
- 以前正常だった画像、機能、証拠を理由なく捨てていないか
- 見た目と当たり判定、入口、前後関係、操作反応が一致するか
- 入店、会話、退出が一続きで操作でき、退屈、分かりにくい、未完成に見える箇所がないか

重大な一項目が不明または不合格なら、平均点で隠さずFAILにします。「完成」「ほぼ完成」「原画準拠」と表現しません。

## 9. 現在の確定事項

- 正規台帳は `art/contracts/user-provided-images.json` です。
- 台帳にはユーザー直接提供22枚を記録しています。全canonical copyは現在、作業ツリー保全済み・版管理待ちです。
- `art/references/target-town.png` は、完全一致の町全体品質目標兼runtime背景です。
- `art/references/target-cutaway.png` はCodex生成候補で、現在のproduction authorityではありません。
- `character_style_authority_20260722_v1.png` が唯一の現行プレイヤー同一性・キャラクター視覚スタイルauthorityです。既存の青いプレイヤー画像と旧候補は履歴・隔離証拠として残しますが、現行promotionには使いません。
